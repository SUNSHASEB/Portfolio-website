01 · The brief

Many apps. One brand.

Imagination Holdings ships dozens of apps. They should feel like one family.

  1. 01Many makers

    PDF tools, AI tutors, Quran learning, social, entertainment and utility apps, built by different studios (9D, ImaginationAI) and teams.

  2. 02One goal

    Once an app hits the store, it should feel like it comes from the same brand.

02 · The portfolio

Six categories. Forty-one apps.

We mapped every product into a category first. Categories became the middle layer of the system.

03 · The problem

Copies drift.

We ran a DSL session in FigJam to compare how the library worked against how it should work.

BeforeCopy & edit

Teams duplicated the locked mother file and edited their copy. Every copy drifted from day one, and fixes never travelled back.

Mother file→Copy→Edit→Drift
AfterPublish & subscribe

The mother file stays locked and is published as a library. Every file links to it, never copies it, so one update reaches every app.

Publish→Subscribe→Override→In sync

05 · Tokenization

Four tiers. Clear owners.

Components never touch raw values. They read intent, and each tier above them has one owner.

  1. 01Core / primitive

    Raw values, like purple.500. Never used by components directly. Never changes per brand.

  2. 02Semantic

    Names what a value is for, not what it is. The only layer components reference.

  3. 03Category theme

    The shared "feel" of all Docu apps, all Health apps, and so on.

  4. 04Product brand

    Final overrides for one app. Only what must differ from its category.

07 · Components

Built once. Used everywhere.

Every component reads semantic tokens, so it re-themes itself in any category or brand.

CTAs in 3 sizes, 3 shapes and every state.

08 · In the wild

Different apps. Same DNA.

Xeno AI, Brainly Tutor and PDF Scanner come from different teams for different users. They still share every button, field, sheet and nav bar. Tap a screen to see what it is built from.

09 · Rapid projects

Speed without forks.

Some apps have to ship in weeks. They use the same locked library; only the workflow around it changes.

  1. 01Pre-approved kits

    Ready-made screens and components teams can use without a review.

  2. 02AI tool integration

    AI tools plugged into the workflow, from brief to screens faster.

  3. 03Fewer approval gates

    The parts are already approved, so only the new parts need sign-off.

10 · Reflections

What it taught me.

  1. 01Link, don't copy.

    The biggest change wasn't a component. It was moving from duplicated files to one published library.

  2. 02Name the intent.

    Semantic tokens let one component serve 40+ apps without anyone touching its code.

  3. 03Every layer needs an owner.

    Core team, category lead, product designer. Clear owners stop "quick fixes" from leaking into the parent.

  4. 04Make the fast path the right path.

    If the system is the quickest way to ship, rapid teams use it instead of working around it.
